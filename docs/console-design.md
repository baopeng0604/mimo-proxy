# MiMo 代理远程网页控制台 —— 设计文档

> 状态：已达成共识，待实现
> 日期：2026-08-19

## 目标

在现有 MiMo Reasoning Content Proxy（`mimo_proxy.py`，Starlette 应用，监听 `8899` 端口）基础上，新增一个可通过公网/局域网远程访问的**只读**网页控制台，用于：

1. **状态指示**：绿点 = 服务正常；红点 = 有问题。
2. **实时终端**：网页上输出命令行日志，实时刷新，方便查看报错。

## 可行性结论

**完全可行。** 项目本身是 Starlette 应用，具备 HTTP + WebSocket 全链路能力，无需引入新技术栈。核心难点不在"能否实现"，而在以下设计取舍，均已逐一定案。

## 设计决策总表

| # | 决策 | 定案 |
|---|------|------|
| 1 | 部署方式 | 同进程挂载，复用现有 `8899` 端口 |
| 2 | 实时通道 | WebSocket 推送日志（单向、只读）|
| 3 | 访问控制 | `.env` 新增 `CONSOLE_TOKEN` 口令 |
| 4 | 状态判定 | 绿 = `/health` 通过 且 最近日志无 ERROR；红 = 服务挂了 或 最近日志有报错 |
| 5 | 历史日志 | `deque(maxlen=1000)` 环形缓冲，打开先灌历史再进入实时 |
| 6 | 操作能力 | **纯只读**，无任何操作按钮 |
| 7 | 登录方式 | Cookie 一次性输入口令，过闸免打扰 |
| 8 | 日志展示 | 等宽终端 + 自动滚动（报错着色），提供暂停滚动开关 |
| 9 | 代码组织 | 拆成 `console.py` 独立文件，`mimo_proxy.py` 导入并注册路由 |

## 详细设计

### 1. 代码组织（决策 9）

新增 `console.py`：包含

- 环形缓冲日志 Handler（`logging.Handler` 子类）
- Console 页面路由（返回 HTML 字符串）
- 登录鉴权中间件（Cookie 校验）
- 状态快照逻辑（绿/红判定）
- WebSocket 路由（历史灌入 + 实时增量）

`mimo_proxy.py` 改动：

- `import console`
- 在现有 `logging.basicConfig(...)` 之后，附加环形缓冲 Handler
- 在 `routes` 列表追加 console 的路由

部署命令不变：`python mimo_proxy.py`。

### 2. 状态指示（决策 4）

判定逻辑（服务端提供快照，前端轮询 `/health` 与状态接口）：

- **绿**：`/health` 返回成功 **且** 环形缓冲中最近日志没有 `ERROR` 级别记录。
- **红**：`/health` 失败/超时（服务挂）**或** 环形缓冲最近日志中出现 `ERROR` 记录（在跑但有问题）。

中间态说明：若服务整个崩了，前端连不上 WebSocket 与状态接口，前端本地判断为红/灰，效果等价于红点。

### 3. 实时日志（决策 2、5、8）

- 挂一个 `logging.Handler`，把每条日志写入 `deque(maxlen=1000)` 环形缓冲（线程安全，加锁）。
- 原始 `logging.basicConfig` 的 stdout 输出保留 —— journalctl 照常可用，二者互不干扰。
- 前端连接 WebSocket 后，服务端先一次性发送缓冲内最近日志（JSON 数组），再实时推送新增行。
- 排除 / 跳过：控制台自身产生的 HTTP access 日志（uvicorn 的 `uvicorn.access`）不进入缓冲，避免刷屏自噪。
- 前端展示：等宽字体终端，自动滚动到底；`ERROR` 红、`WARNING` 黄、其他灰白；提供"暂停自动滚动"开关以便翻看历史。

### 4. 访问控制与登录（决策 3、7）

- `.env` 新增 `CONSOLE_TOKEN`。
- 访问 `http://<ip>:8899/console` 时，若请求未携带有效 token cookie，返回一个简单的口令输入页。
- 提交口令后，服务端校验（`secrets.compare_digest` 防时序攻击），正确则写入 HttpOnly cookie（默认有效期内免登录），随后正常加载控制台页面与 WebSocket。
- WebSocket 握手同样校验 cookie（含 token），阻止直连 WebSocket 绕过鉴权。
- 若未配置 `CONSOLE_TOKEN`：打印警示日志，并默认放行（便于本机调试），但在日志与启动横幅中明确提示。

### 5. 现有接入点（已核对的 Facts）

- 已有 `/health` 端点返回 `{"ok": True}` —— 状态判定复用它。
- 日志走 `logging` 模块，logger 名为 `mimo-proxy`，配置为 `logging.basicConfig(level=INFO, ...)`。
- 启动横幅使用 `print()`，**未走日志系统** —— 实现时顺带把关键启动日志改为 `log.info` 统一，保证控制台历史里能看到启动信息。

## 前端页面信息架构

```
┌─────────────────────────────────────────────┐
│ ● 状态   MiMo 代理 · 绿/红点 | 最近更新时间   │  ← 顶栏
├─────────────────────────────────────────────┤
│  终端区域（等宽字体、自动滚动）                │
│  [12:33:01] [mimo-proxy] ✅ Injected ...     │
│  [12:33:02] [mimo-proxy] ⚠️ Degraded ...     │
│  [12:33:03] [mimo-proxy] ❌ Error ...        │
│  ...                                         │
├─────────────────────────────────────────────┤
│  [暂停自动滚动]                              │  ← 底部可选开关
└─────────────────────────────────────────────┘
```

- 顶栏状态点数据来自状态接口 + WebSocket 心跳。
- 终端采 UI 细节克制：只保留"自动滚动 + 报错着色 + 暂停滚动"，不做多余按钮（决策 6 只读约束）。

## 配置变更

- `.env` / `.env.example` 新增：
  - `CONSOLE_TOKEN=你的口令`
  - （可选）`CONSOLE_ENABLED=true` —— 是否启用控制台，默认启用。
- `DEPLOYMENT.md` 补充控制台访问方式与 token 配置说明。

## 非目标（范围边界）

- 不做"网页上触发重启 / 清空缓冲"等操作功能（决策 6）。
- 不做上游 MiMo API 可达性探测作为状态依据（避免误报）。
- 不做多用户/细粒度权限体系 —— 单个 token 足够。
- 控制台崩了不影响代理本体 —— 二者同进程，页面/WS 仅旁挂日志，不参与请求主路径。
